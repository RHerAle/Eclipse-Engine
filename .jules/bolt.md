
## 2024-05-24 - V8 Math.min/Math.max overhead in inner loops
**Learning:** Using `Math.min` and `Math.max` for bounds checking on every single pixel access in image processing functions (like `blur` and `scharr`) creates a significant V8 engine bottleneck. Loop splitting (processing inner pixels without bounds checking and edges separately) can yield massive speedups (~80% faster for 3x3 filters). However, when splitting loops, it is CRITICAL to ensure boundaries are safely clamped (e.g. using `Math.min(w, r)`) because a small image could have dimensions smaller than the filter radius `r`, causing catastrophic out-of-bounds writes if loops assume `w - r > 0`. Also, when writing the separated edge passes, spatial locality must be preserved (e.g. don't write columns in an outer loop if the array is row-major).
**Action:** Always prefer loop splitting over per-pixel bounds checks in hot paths, but aggressively clamp loop boundaries and explicitly test edge cases (like 1x1 images or kernels larger than the image) to prevent memory corruption. Maintain row-major iteration order.
